# kgen

The generator behind this provider. Almost everything under `internal/service/`,
`modules/`, `examples/` and `docs/` is its output.

For what the inputs mean, the invariants that hold, and the traps, read
[`codegen/README.md`](../../codegen/README.md) first. This file is a map of the
implementation.

## Stages

| Package | Command | Produces |
|---|---|---|
| `schemas` | `kgen schemas` | Resource schemas via tfplugingen, plus the sidecar merges (renames, schema overrides, spec additions) |
| `crud` | `kgen crud` | Resource CRUD and the whole data source, from the SDK |
| `versions` | `kgen versions` | Per-resource Kion version gates |
| `module` | `kgen module` | One Terraform module per resource |
| `examples` | `kgen examples` | `.tf` examples |
| `migrate` | `kmigrate` | Rewrites configurations written for the SDKv2 provider |
| `config` | `kconfig` | Derives `codegen/generator_config.yaml` from the service packages |

`crud` picks a template per archetype (entity, blended, association, parent_list,
compound, and the bespoke ones in `bespoke.go`). `crud_archetypes.yaml` says which
each resource uses.

## Templates

`*.gtpl` files are the emitted code. Edit these, never the generated output. A
template change means `make crud-force`, since `make crud` skips files that exist.

Bespoke templates cover resources whose control flow fits no archetype: the
`app_config` settings singleton, the `account`/`aws_account` convert-and-move
state machine, and the entity-polymorphic `custom_variable_override`.

## Boundaries

`kfs.FS` and `Runner` are the two injected seams, for the filesystem and for
running the external generators. Tests use the mocks in each package's `mocks/`
directory, regenerated by `make generate-mocks`.
