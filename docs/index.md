# Kion Terraform Provider

The Kion Terraform Provider allows you to interact with an installation of Kion.

## Upgrading from the previous provider

Version 1.0 is a new major version built on the Terraform Plugin Framework, published at the same registry address. **Your state migrates automatically.** The provider carries state upgraders that transform old-schema state the first time you plan, and nothing is changed until you apply.

Your `.tf` configuration does need updating, because some attributes were renamed and several blocks became id lists. The `kmigrate` tool attached to every release rewrites them for you; it is a single binary with no dependencies.

See the [upgrade guide](https://registry.terraform.io/providers/kionsoftware/kion/latest/docs/guides/upgrading-from-0.3) for the full procedure and the complete list of config changes.

provider "kion" {

## Schema

### Optional

- `api_key` (String, Sensitive) Kion API key. Can be set with KION_API_KEY environment variable.
- `api_url` (String) Kion API base URL. Can be set with KION_API_URL environment variable.
- `apikey` (String, Sensitive) Deprecated: use api_key instead. Kion API key.
- `apipath` (String) Base path of the Kion API, appended to api_url. Defaults to /api; set to "" for an API mounted at the root.
- `auth_token` (String, Sensitive) Kion authentication token. Can be set with KION_AUTH_TOKEN environment variable.
- `skip_ssl_validation` (Boolean) Skip SSL certificate verification. Can be set with KION_SKIP_SSL_VALIDATION environment variable.
- `url` (String) Deprecated: use api_url instead. Kion API base URL.

### Environment Variables

If you want to configure the provider via environment variables, you can use these below.

```bash
export KION_API_URL="https://kion.example.com"
export KION_API_KEY="app_1_XXXXXXXXXXXX"
# Or use an auth token instead of API key:
# export KION_AUTH_TOKEN="your-auth-token"
export KION_SKIP_SSL_VALIDATION="false"
```

### Importing Resource State

This provider supports [importing state for resources](https://developer.hashicorp.com/terraform/cli/import). You will need to create the Terraform files and then you can run commands like this to generate the `terraform.tfstate` so you don't have to delete all your resources and then recreate them to work with Terraform:

```bash
# Initialize the project.
terraform init

# Import the resource from your environment.
# The number at the end is the ID of the resource in Kion.
terraform import kion_label.example 20

# Verify the state is correct - there shouldn't be any changes listed if you defined
# the resources correctly.
terraform plan
```
