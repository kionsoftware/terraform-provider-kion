
## [1.8.1] - 2026-11-03


### BUG FIXES

- kion_ou_cloud_access_role and kion_project_cloud_access_role no longer plan to destroy and recreate a role when any other attribute changes. cloud_access_role_type_id forces replacement, and when it was left unset it became unknown on every in-place change, so Terraform read it as changed. Sixteen attributes on eight resources had this combination; it was live on the two cloud access roles, whose other attributes update in place. Found by the live migration test, where migrating a role from 0.3.36 planned its replacement.
- kion_webhook: setting owner_user_group_ids or owner_user_ids to an empty set no longer fails the apply with "inconsistent result after apply: was cty.SetValEmpty, but now null". Kion returns an empty owner list as null, as it does for kion_user_group (#147).
- kion_compliance_check: regions = [] no longer fails the apply. Kion stores an empty region list as [""], which read back as a one-element set.
- kion_idms_open_id_access_rule: import now recovers open_id_id, which the by-id read does not return, from the IDMS that lists the rule, as kion_idms_open_id_group_association already did. It was left null, so the next plan replaced the rule.
- kion_project_cloud_access_role, kion_ou_cloud_access_role, kion_cft: reordering aws_session_tags (tags on kion_cft) no longer fails the apply with "Provider produced inconsistent result". Kion returns tags in creation order and keeps a tag it already has, so the read now keeps the configured order, matched on tag_key.
- kion_oauth2_client, kion_permission_scheme: a record deleted outside Terraform no longer fails every refresh with "API returned status 500". Kion answers a by-id read of a deleted record with a 500 rather than a 404; the read now checks the record's list and drops it from state when the list omits it, as kion_app_role already did.
- kion_automation_policy: create no longer fails after Kion has already made the policy, which left it in Kion with nothing in state. Kion answers a create with the bare id, which the provider could not decode. A policy with a scheduled_frequency but no start_date or end_date is no longer rejected with a bare 422: the unset dates were sent as an empty timestamp Kion cannot parse.
